# 複数のダウンローダー

4.0 から、AB は複数のダウンローダーに同時に接続できます。例えば、手元の qBittorrent と NAS 上の別の qBittorrent や aria2 です。各ダウンローダーは**インスタンス**で、それぞれ id、種類、アドレス、アカウント、ダウンロードパスを持ちます。そのうち 1 つが**既定インスタンス**です。

ダウンローダーが 1 つだけなら、動作は 3.x と同じで、画面にダウンローダーの選択も表示されません。

## ダウンローダーの管理

**設定 → ダウンローダー設定** を開きます。上部にすべてのダウンローダーインスタンスが表示され、既定インスタンスには「既定」の印が付きます。

- **編集**：インスタンスをクリックし、下で種類、アドレス、ユーザー名、パスワード、ダウンロードパス、SSL を変更します。
- **追加**：新しいダウンローダー id を入力し、**追加** をクリックします。id に使えるのは英字、数字、`_`、`-` だけです。
- **既定に設定**：インスタンスを既定インスタンスにします。
- **削除**：インスタンスを削除します。既定インスタンスは削除できません。

種類は qBittorrent、aria2、またはプラグインのダウンローダーです。変更後は下部の **保存して再起動** をクリックします。各オプションと `config.json` の形式は [ダウンローダー設定](../config/downloader.md) を参照してください。

## ルールのダウンローダーを選ぶ

ダウンローダーが複数あるとき、次の場所に **ダウンローダー** 欄が表示されます。空欄なら既定インスタンスを使います。

- **RSS の追加**：購読のダウンローダーを選びます。購読とコレクトの両方で使われます。
- **番組の編集モーダル → 詳細設定**：ルールごとにダウンローダーを選びます。

新しいトレントのダウンローダーは次の順で決まります：

1. ルールが選んだダウンローダー。
2. ルールに指定がなければ、購読が選んだダウンローダー。
3. どちらにも指定がなければ、既定インスタンス。

購読から自動で作成されたルールは、購読のダウンローダーを引き継ぎます。上部の検索から追加した番組は既定インスタンスを使います。後で詳細設定で変更できます。

トレントは選ばれたインスタンスのダウンロードパスの下に保存されます。

## トレントの記録先

AB は各トレントを追加したダウンローダーを記録します。その後のリネームと削除は、そのダウンローダーで行われます。

- **ダウンローダーページ**：ダウンローダーが複数あると「ダウンローダー」列が追加されます。一時停止、再開、削除などの一括操作は、各トレントがあるダウンローダーに送られます。
- **トレント一覧**：ルールと未一致トレントの一覧に、ダウンロード済みトレントのダウンローダーが表示されます。

## 変更後の既存トレント

| 操作 | 既存のトレント | 新しいトレント |
| --- | --- | --- |
| ルールを別のダウンローダーに変更 | 元のダウンローダーの元の場所に残り、移動しません。AB は元のダウンローダーで整理を続けます | 新しいダウンローダーのダウンロードパスに入ります |
| 既定インスタンスを変更 | 変わりません | ダウンローダーを選んでいないルールと購読は、新しい既定インスタンスを使います |
| ダウンローダーを削除 | 影響を受けず、そのダウンローダーに残ります。AB はもう接続せず、その中のトレントも整理しません | それを選んでいたルールと購読は既定インスタンスを使います |
| ルールをファイルごと削除 | AB は記録された各ダウンローダーで、そのルールのトレントを削除します | — |

## ダウンローダーに接続できないとき

AB はダウンローダーごとに順にリネームを実行します。接続できないダウンローダーはスキップし、他のダウンローダーは通常どおり処理します。ダウンローダーが利用可能から利用不可に変わったとき、AB は「ダウンローダー接続エラー」を 1 回通知します。回復した後に再び利用不可になると、もう一度通知します。

トレントを追加するときに対象のダウンローダーが利用できない場合、そのトレントは記録されず、次の RSS 更新で再試行されます。

## 3.x からのアップグレード

4.0 にアップグレードして最初に起動したとき、AB は 3.x のダウンローダー設定を id `default` のインスタンスに移し、既定インスタンスにします。既存のトレントはすべて `default` に記録されます。既存のルールと購読はダウンローダーを選んでいないので、既定インスタンスを使います。元の設定ファイルは `config.json.v3.bak` としてバックアップされます。
